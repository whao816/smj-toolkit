## 3. 逐项技术方案

### R1 — TE 谱序（P1-1，P0）

**根因**：`read_te` 按行序返回；`analyze_te` 用梯形积分，x 递减时所有积分反号；`l0/l2` 被 `abs()` 吸收，`l1` 没有 → 只有 S 反号（L0/L2/G/ZT 不变，因此"看起来正常"）。

**改法（上游，C2）**：
1. `landauer.py:23 read_te`：解析后校验 `x` 严格递增；非递增时**排序**并返回 `(rows, order_note)` 或抛错（二选一，见决策 D2）。
2. `landauer.py:62 analyze_te`：统一入口处 `rows = sorted(rows, key=lambda r: r[0])`，输出新增 `"input_energy_order": "ascending"|"descending"|"unsorted"`、`"reordered": bool`。
3. `independent_check.py:86 l0_l1_l2`：同样先排序，保持两路口径一致。
4. 上游删掉 `l0/l2` 的 `abs()`？**不删**——排序后符号已确定，`abs` 保留可保证"排序前"的历史值不跳变；但要在注释里写明"abs 只在已排序数据上是正确性冗余"。

**本包守卫（C1，纵深防御 + 可观测）**：
- `src/smj/analysis.py:241 analyze_te`：调用 vendored 前先做轻量校验（严格递增、无重复能量、无 NaN），把 `te_order` 写进 `analysis.json`；输入非升序时在 `warnings` 记一条（信息性，不阻断，因为 vendored 已排序）。
- `src/smj/stages/aitranss_te.py:144 collect`：现有 `read_te` 只数点数（:148），追加顺序校验，写入 `metadata.te_order_ok`。

**验收**：
- 同一份薁 TE.dat 升序 vs 降序：`S` 一致到 6 位有效数字，且都等于 `+25.93621`。
- 打乱行序（洗牌）：结果与升序一致，`warnings` 含排序提示。
- 重复能量点 / NaN：给出明确错误（不是静默积分）。
- `tests/test_te_order.py` 全绿；golden 不变。

**测试文件**：`tests/test_te_order.py`（升序/降序/洗牌/重复/NaN/单点/空谱）。

**风险**：上游 `analyze_te` 另有消费者 `agenticdft/mcp_server.py:717`、`agenticdft/stages.py:2180`（`junction_analyze` 后处理）→ 改返回字段是**新增键**，不删旧键，风险低；排序会改变"别人依赖行序"的行为，需在上游跑 `pytest agenticdft/tests -k "junction_transport or independent_check"`。

### R2 — 能量窗必须跨 E_F（P1-2a，P0）

**根因**：`config.py:641 _parse_transport` 只校验 `estep>0`、`eend>ener`（:649-650），不要求窗口含 E_F；让整窗落在 E_F 之上的配置合法通过，随后 S 被算成 −919 µV/K 仍判 passed。

**改法（本包，C1）**：
- `eV` 相对窗：`ener <= 0.0 <= eend` 是**配置期就能判定**的（相对量），不满足直接 `ConfigError`，错误信息给出"相对窗必须以 E_F 为 0 点、跨 0"。
- `Hartree` 绝对窗：配置期不知 E_F，改在 `TransportConfig.resolved_window(efermi)`（:242）旁新增纯函数 `window_covers_efermi(efermi)`；`aitranss_te.py:73`（换算处）与 `report.py` 判定处调用，不满足则拒绝/降级（与 R3 联动）。
- 逃生通道：**不加** `allow_outside` 开关（fail-closed；真要做特殊研究，用户可在 R3 里显式覆盖 verdict）。

**验收**：`energy_window=[0.25,0.000499,0.449]`（eV）→ `ConfigError`；`[-0.3,0.0005,-0.05]` → 通过且 `covered=true`；demo 的 Hartree 窗不受影响。

**测试**：`tests/test_energy_window.py`（现有文件追加 3 例）。

**兼容性**：现有 demo 全部是 Hartree 绝对窗，不受影响；eV 相对窗用户若窗口没跨 0，会在配置期拿到明确报错而不是静默算错 → 写进 CHANGELOG「行为收紧」。

### R3 — 判定口径：无适用闸门 / 窗口越界（P1-2b，P0）

**根因**：`criteria.py:273 physics_verdict` 把 `applicable=False` 的 check 记为"不适用"后跳过，若无任何 error 级未过项就返回 `passed`；AZ 族的 `g_in_theory_band`/`seebeck_sign` 都带 `applies_to={'families':('Au-BDT-Au',)}` → 全被跳过 → `passed`。

**改法（本包新模块，C1）**：新建 `src/smj/verdict.py`：

```python
def refine_verdict(verdict, checks, *, efermi, window, is_done, first_incomplete) -> dict
```

注入两类**合成 check**（字段形状与 vendored check 完全一致，这样仍由 vendored `physics_verdict` 归约，不另造一套语义）：

1. `energy_window_covers_efermi`（physical/error）：窗口不含 E_F → `passed=False`，detail 写明窗口与 E_F 数值。
2. `physical_gate_coverage`（physical/error）：过滤 `applicable is not False` 的 physical check 后为空 → `passed=False`，detail 列出 `not_applicable_criteria` 与原因。
3. 可选：`run_complete`（engineering/error）由 R7 负责，不在本模块。

接线：`report.py:475-494`（`build_manifest` 里造 `manifest["verdict"]` 的位置）与 `review.py:596 review_run` 共用同一入口；`manifest["verdict"]` 增加 `gates_applied`/`gate_coverage`/`window_covers_efermi` 三个字段（新增，不删旧字段）。

**验收**：
- P1-2 的合成常数谱 → `physics_verdict != "passed"`（按决策 D3 落 `failed` 或 `inconclusive`），且 `inconclusive_criteria`/`failed_criteria` 里能看到 `physical_gate_coverage`。
- AZ/BPY/SME/alkane 族的正常 run：不因为"BDT 带不适用"就整体降级（它们的 `au_s_bond`、`t_ef_resonance_attribution` 等仍是适用闸门）→ 不会误伤 `test_family.py` 的既有语义。
- 「支持 H0」措辞不再出现在含未适用闸门的 verdict 里。

**测试**：新增 `tests/test_verdict_gates.py`；更新 `tests/test_criteria_failopen.py`、`tests/test_report_verdict.py`、`tests/test_family.py` 的断言。

### R4 — 弛豫收敛验收（P1-3 + 新增④，P1）

**根因**：`aims_tip_relax.collect`（:190-239）只判 `geometry.in.next_step` 存在，`aims.out` 一次都没打开；`au_relax.collect`（:145-183）稍严，但同样不解析收敛标记，却在 metadata 里硬写 `"converged": True`。

**改法（本包，C1）**：
1. 新增共享 helper（建议 `src/smj/stages/_aims_log.py`）：`relax_status(aims_out_path) -> {converged, steps, terminated_normally, last_marker, hit_step_limit}`，判定规则：
   - 取**最后一次** `Present geometry is converged.` / `Present geometry is not yet converged.`；
   - 末尾必须有 `Have a nice day.`（正常结束）；
   - 出现 `maximum number of relaxation`/`Reached maximum number of` → `hit_step_limit=True`；
   - 三者合成 `converged`。
2. `aims_tip_relax.collect`：未收敛 → **抛 `StageError`**（C5，与 `runner.py:515-520` 同款"拒绝标 collected"），信息里带步数、最后标记、日志路径；只有收敛时才把 `geometry.in.next_step` 列入 `artifacts`。
3. `au_relax.collect`：同样解析；`converged` 改为**观测值**，未收敛拒绝。
4. 下游：`electrode_build.prepare`（:35-42）在 `ctx.upstream` 之外再校验上游 state 的 `results["relax"]["converged"] is True`，双保险。

**验收（关键：不能用"缺 next_step"当反例）**：
- 构造"写到 `geometry.in.next_step` + 日志最后一行 `not yet converged` + `Have a nice day`" → `collect` 抛错、状态非 `collected`、`electrode_build` 不产生电极。

### R6 — 活跃作业重跑（P1-5，P1）

**根因**：`prepare`（:267-280）对 `submitted/waiting` 抛 `StageError("正在远端运行…")`，`run_stage` 的 `except SmjError`（:608-616）**无条件**把状态改成 `failed`；`run()`（:618-669）只对 `finished` 有补 collect 分支，没有 `waiting` 分支 → 下一次 run 保护失效、重复提交（实测 424242 覆盖 12345）。

**改法（本包，C1）**：
1. `run()` 循环开头新增：`status in ("submitted","waiting")` 且非 `force` → 走 `self.wait(key)`（带超时），结束再 `collect`；与 `finished` 分支合并成一个 `_resume_active()` 帮助函数。
2. `run_stage` 的异常处理区分类型：`ActiveJobError`（新子类，`prepare` 抛出）→ **不改状态**，返回 `StageOutcome(status=<当前>, ok=False, message=...)`；其余 `SmjError` 维持 failed。
3. 若 `wait` 超时仍是 `waiting`，返回 `ok=False` 且**保留** `waiting`，`run()` 中止后续阶段（已有逻辑 :664-666）。

**验收**：
- `waiting`+job_id → `run_stage` 后状态仍 `waiting`，`job_id` 未变，无第二次 `sbatch`。
- 再次 `run` → 走 `wait` 分支，不产生新 job_id。
- `--force` → 仍按显式语义重跑（覆盖保护）。

**测试**：`tests/test_rerun_active_job.py`（沿用 `.tmp/verify/runner` 的 fake remote 手法，把 fake session 固化成 fixture）。
